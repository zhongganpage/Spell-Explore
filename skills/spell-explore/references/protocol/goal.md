# the locked goal file (goal.md)

this file is the single locked goal file of the project. it is separate from the dossier and it is locked: the project never changes it, it carries no version (the versioning rule explicitly excludes it), and workers cite it and never edit it. every entry in the dossier, every fresh summary, idea report, route and review points back to this file as the single source for the problem statement and the notation. a change of meaning here would mean a new project, not an edit.

## how this file is created (the round-1 flow note)

at the beginning of the initial round the Coordinator asks the user for the rough idea and makes it the goal, writing it into this file — the precise statement and the notation, written here and nowhere else. the Coordinator does not create anything else. the round-1 setup happens before the round clock starts and is not counted in the 138-minute budget; at the same moment the user also chooses the number of rounds. the round start is announced and written in the dossier before any agent spawns, and the clock starts only after this file is written and locked.

the round that follows runs the fixed sequence Creator → Producer → Selector within the 138-minute budget, whose binding per-phase windows are: 0–20 the Creator's phase-1 workers think (≤10 min) and write their summaries (≤10 min), the fresh summaries ready by ~20 min; 20–45 the Producer's report worker writes the idea report; 45–63 the hygiene linter (layer 1 ≈3 min, layer 2 ≈7 min) and the examine worker (cap 8 min) decide sufficiency; 63–103 the Selector's panel runs; 103–118 the PI rebuts and modifies the route while the promoter writes its nearest true version note; 118–138 the swarm and the resumed BCD reviewers decide. the goal file is written before 0, and the clock does not start until it is locked.

## statement

<to be written by the Coordinator at round-1 start, from the user's rough idea: the precise statement of the goal, in full, with every term defined. this is the statement the accepted routes together must achieve, and nothing else is the goal.>

## notation

<one fixed block. every dossier entry and every artifact must use this notation and no other. the block is fixed at round-1 start; it is notation-locked — it changes only by recording the change as a dated entry in the dossier, never by editing this file, which keeps the notation exactly as written here.>

## what counts as achieving this goal

a route is accepted only by the double gate: ≥2/3 of the swarm workers and ≥2/3 of the resumed BCD reviewers accept. a single route or a set of accepted routes together achieves this goal when they cover the statement above. the milestone is Lean-led: the required condition is the goal node of dependency-graph.json reachable from the [Formalized] or [Hired] assumptions; the 3/3 swarm + 3/3 BCD unanimity is the presentation bar for the manuscript, not the reachability condition. when the goal node is reachable with full consensus, the Coordinator writes the report about it in PDF, called the manuscript, and records it in the dossier. when the reachability holds without the unanimity, the Coordinator reports the formalization milestone to the user, who decides how to proceed — write the manuscript, or keep going.

## citing this file

workers restate the problem in their own words only to check for definition drift; the statement and the notation here are the single source and are never re-derived or replaced. this file is excluded from the versioning rule: it is locked and the project never changes it.
